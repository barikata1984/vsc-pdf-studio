# 表示性能の測定基準 (変更前の記録)

## 目的

change `improve-render-performance` の各手順の前後で、PDF の表示にかかる時間と資源の使用量を同じ条件で測り、
効果があった手順と効果がなかった手順を数値で区別する。この文書は測定の条件と手順を定め、値を書き込む表を用意する。
値は測定のたびにこの文書へ追記する。

## 測定環境

- クライアント: Windows。VS Code の Remote SSH で Linux の作業機に接続し、Webview もクライアント側で描画される。
- サーバー: Linux (作業機)。リポジトリと拡張機能の作業ツリーはここにある。
- VS Code の版: 1.135.0 (コミット 08d4889f9ec4a1685d257b9b95de036c8e1ce1e5、x64)。`code --version` で取得。
- 拡張機能の起動方法: 作業ツリーから拡張機能開発用のウィンドウ (Extension Development Host) を起動する。
  導入済みの版ではなく作業ツリーの内容が動いていることを、変更履歴の版番号か動作の差で毎回確かめる。
- 画面の画素密度: 測定時の `window.devicePixelRatio` を記録する (値: 未測定)。
- 指描画の設定 `pdfStudio.allowFingerDrawing` の値を測定ごとに記録する (既定は未確認のまま扱わない)。

## 測定手順

各手順を別々に行い、間に文書を開き直して状態を揃える。Webview の開発者ツール (コマンドパレットの
Developer: Open Webview Developer Tools) のコンソールに出る計測ログを、該当する記録の下にそのまま貼る。

1. 初回表示: 文書を開いてから最初のページが表示されるまで。開く直前にコンソールを消してから開く。
2. 連続スクロール: 先頭から末尾まで一定の速さでスクロールし、途中で表示が止まる箇所と所要時間を記録する。
3. 連続拡大縮小: 拡大と縮小を交互に 5 回行い、各回の反映までの時間を記録する。
4. ウィンドウ寸法変更: エディタの幅を数回変え、そのたびの再表示の時間を記録する。

各手順で、必要なら開発者ツールのメモリ使用量と保持しているページ数も記録する。
