## Why

この拡張機能は、文書を開くときと拡大率や表示寸法が変わるたびに、PDF の復号と解析から全ページの描画、文字層の構築、縮小画像の生成までをやり直す。そのため、初回表示、拡大縮小、長い文書のスクロールがページ数に応じて重くなる。

## What Changes

- 第 1 群として、解析済み PDF を使い回し、全ページ分の空の枠を作ったうえで、最初のページ、表示中のページ、その前後だけを描画する。拡大率や表示寸法が変わったときは古い描画を中止し、表示範囲だけを描き直す。
- 第 2 群として、PDF の解析と描画を別の処理系で行い、縮小画像をページ一覧の表示時に低い解像度で生成する。文字情報は本文の描画から分離し、検索時に未取得分を読み込む。スクロール方向のページを優先して先読みする。
- 第 3 群として、表示範囲から離れたキャンバスを解放し、現在ページの判定を全ページ走査から交差監視へ変更する。計算後の倍率が変わらない場合は再描画せず、不要になったページの PDF.js 側の資源も解放する。
- 既に追加した所要時間の記録は開発者向けの診断手段として残すが、性能値の採取や比較を各群の開始条件と完了条件にはしない。
- 各群の完了時には、自動テストと静的検査に加え、文書の表示、検索、注釈の保存と再表示を確認する。
- 高精細表示への対応は、描画負荷を増やしうるうえ、今回優先する 3 項目へ直接は効かないため、この変更の範囲から外す。
- **BREAKING** ではない。保存形式、ファイル形式の互換性、既存の注釈データの読み書きは変更しない。

範囲外（別の change として扱う）:

- 画面の画素密度に応じた本文と手書きの高精細表示
- 保存形式の見直し（保存のたびに元の PDF 全体を埋め込む方式）と、外部からファイルが更新されたことの検出
- Webview へ元 PDF と編集済み PDF を二重に送っている初期転送の一重化
- 背面に回ったタブの資源解放
- 複数倍率の描画結果の保存、独自ワーカー、`OffscreenCanvas`、WebGL による独自描画、画質の自動低下

## Capabilities

### New Capabilities

- `render-instrumentation`: 表示処理の各段階の所要時間と、描画要求ごとの開始、完了、中止を開発者が確認できるようにする能力
- `pdf-worker-rendering`: PDF の解析と描画を画面の応答から切り離して行う能力
- `thumbnail-generation`: ページ一覧用の縮小画像を本文の描画から独立して作る能力
- `viewport-page-rendering`: 表示中のページとその近傍を優先して描画し、不要な描画と再描画を避ける能力

### Modified Capabilities

（無し。`openspec/specs/` に既存の仕様は無い。）

## Impact

- Webview 側の表示処理一式（PDF の保持、ページの枠、描画順、文字層、縮小画像、拡大縮小、スクロール位置の判定）
- 表示中ページのみ描画する前提が影響する既存機能（文字の検索、ページ一覧、現在ページの判定とページ移動、手書き、蛍光ペンと下線と取り消し線、入力欄、付箋、テキスト選択、目次からの移動）
- Webview の HTML を組み立てる拡張機能本体の一部（PDF.js の処理系の読み込み方）
- 拡張機能の変更履歴
- 外部依存の追加は無い。同梱している PDF 表示ライブラリの版も上げない。
