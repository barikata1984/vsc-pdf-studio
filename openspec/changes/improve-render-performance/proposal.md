## Why

この拡張機能は PDF を Webview に表示するとき、拡大率が変わるたびに文書全体を読み直し、全ページの描画、テキスト層の構築、サムネイルの生成を 1 本の流れで最後まで終えてから画面へ反映する。しかも解析と描画をすべて画面の応答を担う同じ処理系で行い、描画の解像度は文書全体の総画素数の上限から決まる。その結果、ページ数の多い文書ほど初回表示と拡大縮小が遅く、高精細画面では手書きの筆跡がぼやける。遅さの原因を推測で潰す段階は終わり、計測して裏を取りながら順に直す必要がある。

## What Changes

- 読み込みから表示までの各段階に所要時間の計測を入れ、描画要求ごとの開始と完了と破棄を記録できるようにする。この段階では利用者から見える動作は変えない。
- PDF の解析と描画を、画面の応答を担う処理系から切り離した別の処理系で行う。
- サムネイルの生成を本文の描画から切り離し、ページ一覧を表示するときに低い解像度で作る。
- 表示中のページとその隣接ページだけを描画し、離れたページの描画結果は解放する。拡大率や表示寸法が変わったときは進行中の描画を中止し、文書は読み直さずに使い回す。ページの枠は全ページ分を正しい高さで保持し、文字の検索は描画とは独立した索引で行う。
- 描画の解像度の上限を文書全体の合計からページ単位に改め、本文用と手書き用の両方のキャンバスが画面の画素密度を反映するようにする。
- **BREAKING** ではない。保存形式、ファイル形式の互換性、既存の注釈データの読み書きは変更しない。

範囲外（別の change として扱う）:
- 保存形式の見直し（保存のたびに元の PDF 全体を埋め込む方式）と、外部からファイルが更新されたことの検出
- Webview へ元 PDF と編集済み PDF を二重に送っている初期転送の一重化
- 背面に回ったタブの資源解放

## Capabilities

### New Capabilities
- `render-instrumentation`: 表示処理の各段階の所要時間と、描画要求ごとの開始・完了・中止を観測できるようにする能力
- `pdf-worker-rendering`: PDF の解析と描画を画面の応答から切り離して行う能力
- `thumbnail-generation`: ページ一覧用の縮小画像を本文の描画から独立して作る能力
- `viewport-page-rendering`: 表示中のページとその近傍だけを描画し、不要になった描画を解放・中止する能力
- `high-dpi-rendering`: 画面の画素密度に応じた解像度で本文と手書きを描く能力

### Modified Capabilities

（無し。`openspec/specs/` に既存の仕様は無い。）

## Impact

- Webview 側の表示処理一式（描画、テキスト層、サムネイル、拡大縮小、スクロール位置の判定）
- 表示中ページのみ描画する前提が影響する既存機能: 文字の検索、ページ一覧、現在ページの判定とページ移動、手書き、蛍光ペンと下線と取り消し線、入力欄、付箋、テキスト選択、目次からの移動
- Webview の HTML を組み立てる拡張機能本体の一部（解析用の処理系の読み込み方）
- 拡張機能の版番号と変更履歴
- 外部依存の追加は無い。同梱している PDF 表示ライブラリの版も上げない。
